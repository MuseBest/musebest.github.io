<p>To learn QA testing online, start with manual testing, learn to write test cases and bug reports, practise on free practice sites, then move to API testing and automation. <h2 id="what-qa-testing-is">What QA testing is</h2>
<p>QA testing is the work of finding problems in software before it reaches users. A QA tester, also called a software tester, tries an app in many ways, records what breaks, and reports each problem clearly so a developer can fix it.</p>
<p>There are two main kinds of testing. Manual testing means a person clicks through the app and checks it by hand. Automation testing means writing small programs, called test scripts, that run the checks automatically.</p>
<p>QA testing is not the same as software testing, although the two terms overlap. Software testing is the act of running tests. QA is the wider job of making sure quality is built into the whole process, from planning to release. In job adverts the two terms are often used for the same role.</p>
<p>A tester works in an Agile team, which builds software in short cycles called sprints. The tester checks each new feature during the sprint, reports bugs in a tool such as Jira, and checks the fixes before release. Clear writing matters as much as technical skill.</p>
<h2 id="step-1-learn-manual-testing-basics">Step 1: Learn manual testing basics</h2>
<p>Start with the software development life cycle: planning, building, testing, and release. Learn what happens at each stage and where testing fits.</p>
<p>Next, learn to write a test case. A test case is a written check with four parts: what you will do, what you expect to happen, what actually happened, and whether it passed or failed. For example, a test case for a log in form might say: enter a correct email and password, expect the user to reach the home screen, and record the result.</p>
<p>Then learn to write a bug report. A bug report has five parts: a clear title, the steps to reproduce the bug, what you expected, what actually happened, and the environment, which means the device, browser, and app version. A good bug report lets a developer reproduce the bug in minutes.</p>
<p>Learn the common types of testing too. Functional testing checks that a feature does what it should. Usability testing checks that it is easy to use. Regression testing checks that a new change did not break old features.</p>
<h2 id="step-2-learn-test-design-techniques">Step 2: Learn test design techniques</h2>
<p>Test design techniques are methods for choosing which tests to write. They help you find bugs with fewer tests.</p>
<p>Equivalence partitioning means grouping inputs that should behave the same way, then testing one from each group. For example, an age field that accepts ages 18 to 65 has three groups: under 18, 18 to 65, and over 65. Test one value from each group.</p>
<p>Boundary value analysis means testing the edges of each group. For the same age field, test 17, 18, 65, and 66. Bugs love edges, because that is where developers make off by one errors, which is a mistake where the code allows one value too many or too few.</p>
<p>Decision tables help when a feature has several conditions. A discount that depends on membership and order value has four combinations: member or non member, with a big or small order. A decision table lists all four and the expected result for each.</p>
<p>State transition testing checks how an app moves between states. A shopping cart moves from empty to full to checked out. Test each move, and test the wrong moves too, such as checking out with an empty cart.</p>

<h2 id="step-4-learn-api-testing">Step 4: Learn API testing</h2>
<p>An API, which stands for application programming interface, is the way two pieces of software talk to each other. When an app shows your bank balance, it asks the bank API for the number.</p>
<p>Learn Postman, which is the standard free tool for API testing. In Postman, you send a request to an API and you check the response. The response has a status code, which is a number that says what happened: 200 means success, 404 means not found, and 500 means a server error. Learn these three codes first.</p>
<p>Practise on the API Challenges site, which gives you a free API to test. Write test cases for each endpoint, which is one address in the API. Check that a correct request returns the right data, that a wrong request returns a clear error, and that a request with no login is refused.</p>
<p>API testing is a skill that employers value, because many modern apps are built on APIs. A tester who can test both the screen and the API is more useful.</p>
<h2 id="step-5-learn-automation-one-tool-at-a-time">Step 5: Learn automation, one tool at a time</h2>

<h2 id="step-6-prepare-for-istqb-foundation-optional">Step 6: Prepare for ISTQB Foundation, optional</h2>
<p>ISTQB, which stands for the International Software Testing Qualifications Board, offers the best known QA certificate. The Foundation Level, called CTFL, is the entry level exam, and it covers testing principles, the test process, static testing, test design techniques, test management, and tool support. The syllabus is version 4.0, and it is free to download.</p>
<p>The exam has 40 multiple choice questions, lasts 60 minutes, or 75 minutes if English is not your first language, and needs a 65 percent pass mark. There are no prerequisites, so anyone can sit the exam.</p>
<p>The fee depends on your country and the board you book through. In the US, the exam costs 229 US dollars through AT*SQA, the official exam provider for the American board, ASTQB. The ASTQB 2026 price list also lists 249 US dollars for advanced exams and 199 US dollars for specialist exams. In other countries the fee differs: for example, the UK fee is listed at 200 pounds plus VAT. Check the <a href="https://astqb.org/istqb-faqs/what-is-the-price-of-an-istqb-exam/" rel="noopener" target="_blank">ASTQB exam prices page</a> and your own national board before you book. The <a href="https://www.istqb.com/exam/istqb-exam-cost/" rel="noopener" target="_blank">ISTQB exam cost page</a> also lists fees by country.</p>
<p>Is the certificate worth it? It helps for junior roles, because it shows you know the standard terms and methods. It does not prove you can test well, and it does not replace practice. A good plan is to study the syllabus for free, practise on real sites, and take the exam only when you are ready to apply for jobs.</p>

<h2 id="common-mistakes">Common mistakes</h2>
<ul>
<li>Do not jump to automation before you learn manual testing, because you cannot automate what you do not understand.</li>
<li>Do not write vague bug reports, because a developer cannot fix a bug they cannot reproduce.</li>
<li>Do not test only the happy path, because bugs hide in error cases and edge cases.</li>
<li>Do not test a live site without permission, because you can break real data and real users.</li>
<li>Do not learn three automation tools at once, because you will mix up their commands.</li>
<li>Do not skip SQL, because many testing jobs need basic data checks.</li>
<li>Do not pay for an expensive bootcamp before you try the free route, because you may not enjoy the work.</li>
<li>Do not ignore the ISTQB syllabus, because it teaches the standard terms employers use.</li>
</ul>
<h2 id="risks-and-scams-to-watch-for">Risks and scams to watch for</h2>
<p>Paid QA courses attract the same scams as other online courses. Check before you pay. A real course names its teacher, shows a full syllabus, and lets you see sample lessons. A fake course hides the teacher and pressures you to pay today.</p>
<p>Watch for these warning signs. The course promises a guaranteed job or a set income. The price is only shown after a sales call. The certificate is called accredited but no accrediting body is named. The seller asks for payment by bank transfer or gift card.</p>
<p>Job scams also target QA beginners. A real employer never asks you to pay for a job, a training course, or equipment before you start. A real employer never asks for your bank details, your password, or a copy of your ID in the first message.</p>
<h2 id="frequently-asked-questions">Frequently asked questions</h2>
<h3 id="can-i-learn-qa-testing-without-coding">Can I learn QA testing without coding?</h3>
<p>Yes, for manual testing. Manual testing needs logic, detail, and clear writing, not code. Automation testing needs basic coding.</p>
<h3 id="how-long-does-it-take-to-become-a-software-tester">How long does it take to become a software tester?</h3>
<p>Manual testing takes 2 to 3 months of steady study. Automation adds another 2 to 3 months, because it needs basic coding.</p>
<h3 id="is-istqb-certification-worth-it">Is ISTQB certification worth it?</h3>
<p>It can help for junior roles, because it shows you know the standard terms and methods. It does not prove you can test well, and it does not replace practice. Study the free syllabus first, and take the exam when you are ready to apply for jobs.</p>
<h3 id="do-i-need-a-degree-for-qa-testing">Do I need a degree for QA testing?</h3>
<p>No. Most QA roles ask for a certificate or proven practice, not a degree. Employers care more about your test cases, bug reports, and portfolio than about a university qualification.</p>
<h3 id="should-i-learn-manual-or-automation-testing-first">Should I learn manual or automation testing first?</h3>
<p>Learn manual testing first. It teaches you how to think like a tester and how to write clear bug reports. Automation builds on those skills.</p>
<h3 id="which-automation-tool-should-i-learn-first">Which automation tool should I learn first?</h3>
<p>Pick by language. Learn Playwright with JavaScript if you are new to coding, because it is modern and fast growing. Learn Selenium with Python if you already know Python.</p>
<h2 id="conclusion">Conclusion</h2>
<p>To learn QA testing online, start with manual testing, learn test design techniques, practise on free practice sites, then add API testing and automation one tool at a time. Follow the 8 week plan, build a small portfolio, and consider the ISTQB Foundation exam when you are ready to apply for jobs.</p>
